# アカウント・貸与物のライフサイクル(情シス側チェック)

会社に情シスがいない前提で、担当者が兼務できる粒度で書く。

## 入社時

- アカウント発行: メール / チャット / グループウェア / 業務システム / 共有ドライブ。**部署の標準セット**を決めておき、そこから最小で始める(初期から広い権限を渡すと、退職時に何を止めるべきか分からなくなる)
- 多要素認証を初日に設定させる。パスワードの初期値は初回ログインで変更
- 貸与物: PC / スマホ / 鍵 / 社員証・入館証 / 名刺。**貸与台帳に記録してから渡す**(識別番号・貸与日・受領確認)
- セキュリティのルール(私物利用・持ち出し・共有パスワード禁止など)を初日に説明し、説明した記録を残す

## 在籍中

- 権限は「足す」より「見直す」機会が要る。四半期または半期で棚卸し(アカウント台帳の権限レベルを見直す)
- 貸与物の交換・追加は都度台帳へ

## 退職時(最終出社日までに一覧化しておく)

- 停止のタイミングを決める(最終出社日か退職日か)。有給消化中もアクセスさせるかは会社の運用
- アカウント停止・削除の順: まず**停止**(削除はデータ移管後)。メール転送・共有ドライブの所有権移管・引継ぎ先への権限付与
- **共有パスワードの変更**、管理者権限の付け替え、外部サービス(SNS 公式アカウント等)の権限確認
- 貸与物の回収と台帳への返却記録。データ消去の記録(PC の初期化日・実施者)
- 退職後も残る例外(社宅・保険関係の連絡先など)は台帳の備考に
